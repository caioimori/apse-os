# Story 2.1 — Auth + Organizations

## Contexto
Fundação de multi-tenant. Usuário loga por magic link, cai numa org (cria se não tiver) e passa a ver SÓ dados dela (RLS já garantido pela migration 0001). Base pra todas as stories seguintes.

## Acceptance Criteria

### AC1 — Login por magic link
**Given** usuário acessa `/login`
**When** informa email válido e clica "Enviar link"
**Then** Supabase envia magic link; clique no link loga e redireciona pra `/`

### AC2 — Sessão persistente via cookies (SSR)
**Given** usuário logado
**When** recarrega qualquer página
**Then** sessão permanece (cookies HTTP-only, @supabase/ssr)

### AC3 — Middleware protege rotas autenticadas
**Given** usuário não logado tenta `/orgs` ou `/dashboard`
**Then** redireciona pra `/login?next=<origem>`

### AC4 — Onboarding cria primeira org
**Given** usuário logado sem membership
**When** acessa qualquer rota protegida
**Then** redireciona pra `/onboarding` que exige `name` e `slug` de org, cria org + member `owner`

### AC5 — Módulo organizations expõe API pública
**Given** módulo `@apse/modules-organizations/api`
**Then** exporta: `listMyOrgs`, `getOrg`, `createOrg`, `inviteMember` com zod schemas

### AC6 — Contract test da API
**Given** contract test em `tests/contract/organizations.spec.ts`
**Then** valida shapes de input/output dos 4 métodos

### AC7 — RLS testado
**Given** 2 users em 2 orgs diferentes
**When** user A consulta `organizations`
**Then** vê só a dele (RLS isolamento)

### AC8 — Página `/orgs` lista orgs do usuário
**Given** usuário logado com 1+ orgs
**Then** renderiza cards com nome, slug, role do user

### AC9 — Design tokens aplicados
**Given** todas as telas novas (login, onboarding, orgs)
**Then** usam tokens do caioimori-DS; zero hex hardcoded (ADR-006)

## Scope IN
- `@apse/shared-auth`: client SSR + browser, hook `useUser`, middleware helper
- `@apse/shared-db`: helper `serverClient`, `browserClient` (já existe)
- `@apse/modules-organizations`:
  - `src/api/contracts.ts` (zod + types)
  - `src/api/index.ts` (`listMyOrgs`, `getOrg`, `createOrg`, `inviteMember`)
  - `src/db/repo.ts` (queries via supabase client)
- `apps/web`:
  - `/login`
  - `/auth/callback` (processa magic link)
  - `/onboarding`
  - `/orgs` (lista)
  - `middleware.ts` (proteção)
- Contract test + RLS test

## Scope OUT
- Convite por email real (mock — email fica em log até Passo 11)
- Troca de org ativa (fica pra Story 3.1+ quando listar clientes)
- Configurações da org (domain, billing, etc)
- Row-level de members (já tem RLS da migration 0001)
- OAuth (Google/GitHub) — magic link basta no MVP
- Recuperação de senha (magic link é stateless)

## Dependências

- JWT expiry: default (1h)
