# Story 3.1 — Clients CRUD

## Contexto
Primeiro dado de negócio de verdade. Dogfood #1 — Caio cadastra os 4 clientes reais da SINAPSE (MindLoop + outros 3). Base pra Story 4.1 (contracts) que referencia `client_id`.

## Acceptance Criteria

### AC1 — Migration com RLS por org_id
**Given** `supabase/migrations/*_create_clients.sql`
**Then** cria tabela `clients(id, org_id, kind, name, document, email, phone, notes, status, timestamps)` com RLS por `org_id`, índice `(org_id, name)`, FK cascade pra `organizations`

### AC2 — Módulo @apse/modules-clients com API pública
**Then** exporta: `listClients`, `getClient`, `createClient`, `updateClient`, `archiveClient` com zod schemas

### AC3 — Contract tests cobrem schemas
**Then** ≥ 12 testes vitest passando (happy path + rejeições)

### AC4 — Lista de clientes `/orgs/[id]/clients`
**Given** org com clientes cadastrados
**Then** tabela densa com nome, tipo (PF/PJ), documento mascarado, email, status (StatusPill), ordenação por nome

### AC5 — Busca client-side
**Given** campo de busca
**When** usuário digita
**Then** filtra por nome/documento/email em tempo real (debounce 200ms)

### AC6 — Criar cliente `/orgs/[id]/clients/new`
**Given** form com kind (PF/PJ), name, document (máscara CPF/CNPJ), email, phone, notes
**When** submete válido
**Then** cria no DB, redireciona pra detalhe

### AC7 — Editar cliente `/orgs/[id]/clients/[clientId]`
**Given** cliente existente
**Then** form pré-preenchido, permite update de todos campos exceto kind/document (criar novo pra mudar tipo)

### AC8 — Arquivar (soft delete via status)
**Given** cliente ativo
**When** clica "Arquivar"
**Then** status → 'archived', some da lista default, aparece só em filtro "Arquivados"

### AC9 — Validação CPF/CNPJ
**Given** input de documento
**Then** zod valida: CPF (11 dígitos) ou CNPJ (14 dígitos); rejeita com mensagem clara

### AC10 — Design tokens aplicados
**Then** zero hex hardcoded; todas as telas dark-compatible
